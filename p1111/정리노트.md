- 특성을 너무 늘리면 **과대적합** → **규제**(Ridge, Lasso) (`p1111_05~07`)
- 글자 열 `OneHotEncoder` + 입력받아 예측 (`p1111_08`)

## 핵심 개념
| 용어 | 뜻 |
|---|---|
| 다항회귀 | 특성 **1개**를 제곱해서 곡선으로 |
| 다중회귀 | 특성 **여러 개**를 함께 사용 |
| `PolynomialFeatures(degree=2)` | 원래값 + 제곱 + **서로 곱한 값**까지 (3개 → 9칸) |
| `include_bias=False` | 1로 채운 칸을 안 붙임 (절편은 LinearRegression이 계산하니 중복) |
| 과대적합 | 학습 점수는 높은데 테스트 점수가 뚝 떨어짐 (외워버림) |
| 규제 | 과대적합을 막는 것. **정규화 후** 사용 |
| `Ridge(alpha=)`, `Lasso(alpha=)` | alpha가 **클수록 규제 강함** |
| 다중공선성 | 원핫 칸끼리 겹치는 문제 → `drop='first'`로 한 칸 제거 |

## 자주 한 실수
- `degree=15`, 데이터 15개에 3,875칸 → 테스트 점수 −31,356 (과대적합)
- `lr`(train_poly로 학습)에 정규화한 값을 넣음 → −16점. **모델이 뭘로 학습했는지** 보고 맞춰 넣기
- `PolynomialFeatures`는 칸 순서가 `[길이, 길이²]` (직접 만든 column_stack과 반대)
- `coef_[0]`, `coef_[1]` 번호 빠뜨리면 shape 에러
- `list = [...]` 변수 이름 ❌ → `list()` 함수가 망가짐
- 셀 실행 순서가 섞이면 서로 다른 데이터로 비교하게 됨 → Restart 후 위에서부터
